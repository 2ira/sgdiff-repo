15归因结论

同预算，不同信号

随机删边与按度删边删掉一样多的边（2253 vs 2248），但前者保留度信号、后者专杀它——同一预算下必须看「动了哪个性质」，而不是「动了多少边」。

度启发式 AUC：clean 0.643 → del 0.596 → del_hub 0.525；共同邻居 AUC：0.723 → 0.572 → 0.559

GCN 族的命门是特征，不是聚合

全图内积解码器把结构当平滑算子、把属性当信号：置零特征后全部跌到 0.43–0.50，而删边只掉 0.04–0.10。层级别测量显示，特征伤害在第 1 层之前就已发生，结构伤害则在第 2 跳才出现。

GCN：clean 0.825 / 特征置零 0.366 / del +0.049 / del_hub +0.059；层级别：GCN 的 L1 线性探针 0.604（结构探针下 L1≈0.84 不动）

子图族死于「输入饥饿」——修边能救，修特征不能

测试边在提取前就被移除，k=1 时唯一判据是共享邻居路径。删边把这条路径砍掉七成，子图从 10.7 节点缩到 5.4–7.0。按 CN 先验把边补回去，收益集中在子图族；把损坏的特征按结构重建，收益集中在 GCN 族——同一修复，效果相反。

共享邻居率 clean 0.225 → del 0.073 → del_hub 0.054；SEAL del +0.137 / ins +0.017；修复：CN 补边把 SGDiff 从 0.522 拉到 0.619，而把 GCN 的损坏特征按结构重建：0.629 → 0.678

SGDiff：只有结构分支在说话

融合支路的开关证明特征支路是死的（只留特征 = 随机），因此它对 feature_shuffle 免疫、对删边最脆弱，且脆弱点不是权重而是判据本身：两类似然之差在证据变薄时向先验坍缩。

clean 0.729 / 只用结构 0.728 / 只用特征 0.497；del +0.235（seed 波动 ±0.072）

鲁棒性来自自环，不是对称归一化（原假设被证伪）

同一套权重只换传播算子：对称归一化、行均值、完全不归一化三者在删边下几乎一样，而去掉自环才真正掉点。自环是「邻居被打掉时仍保留自身信号」的恒等通路。

GCN del：sym 0.781 / row 0.771 / sum 0.765 / noloop 0.708（−0.073）；SAGE 无自环，sym 与 noloop 完全相同——构造性对照

多给证据 ≠ 修好：k=2 抬高上限，不改变脆弱性

把 SEAL 的包围子图从 1 跳扩到 2 跳重训，clean AUC 涨了约 0.07，但相对 clean 的删边缺口没有缩小——脆弱性取决于「如何使用证据」，而非「看到多少」。

SEAL：clean 0.781 → 0.856（+0.075），del 0.644 → 0.648；缺口 0.137 → 0.208

密度决定「哪一半」致命

同样的 50% 删边，稀疏图上砍掉七成本地 2 跳信号，密集图上只砍掉三成：子图族的删边脆弱性是稀疏性的函数，不是权重的属性。密集图上换成 hub 插边才致命，因为它摧毁的是「度归一化」连通性。

Cora 共享邻居率 −70% → SGDiff del +0.235；USAir −28% → SGDiff del +0.036；USAir Jaccard AUC 0.897 → 0.640，PENCIL ins_hub +0.190

重训验证：自环负责删边鲁棒性，改数据只修得动特征通道

把 2 层 GCN 从头重训，每次只改一个部件：去掉自环，删边伤害直接翻倍；只把对称归一化换成行均值，几乎不动；把结构描述符拼进输入（+cnfeat），删边缺口也不缩小。但把输入特征按结构平滑（+smooth）能把特征通道的伤害显著压低——也就是说，“哪个部件负责哪种伤害”是可分离的，而且两条通道要两种修法。

cora：del 伤害 base 0.056 / noloop 0.114 / row 0.061；feature_shuffle 伤害 base 0.167 → +smooth 0.147

「看起来合理」的边几乎隐形

同配插边把同配性抬到 0.881（高于 clean），对所有模型伤害 ≤0.04，对 GAT 甚至是增益；只有异配边（最不合理的边）才带来 0.02–0.05 的伤害。没有模型直接读同配性——它只是平滑假设。

同配性 clean 0.812 / ins_homo 0.882 / ins_hetero 0.511；GAT ins_homo -0.023

小 ΔAUC 只是方向，不是量级

把 seed 之间的差异当误差棒是错的：要估计的量来自 pair 采样，而 clean 与 probe 在同一批 pair 上打分，所以区间必须配对重采样才能得到。做完之后，0.02–0.03 一档的差距大多跨过 0——它们能说「这个探针伤了这个模型」，不能说「伤得比另一个多」。

sgdiff del ΔAUC +0.211 [+0.107, +0.301]；CI 覆盖 0：seal/feat_shuffle、pencil/feat_shuffle、pencil/ins_hub、sgdiff/feat_shuffle、sgdiff/ins_hub

门控问错了问题，所以修复无效

按「图上还有没有证据」路由，在攻击前就已经命中大半 pair，于是删边缺口继承 k = 2：整条阈值前沿都落在「始终 k2」上，没有可用工作点。而另一条退路——用 CN 先验补回被删的边——在它要救的那些 pair 上几乎恢复不了证据，因为 CN 先验只有对已有共同邻居的候选才有定义。「模型在有证据时会怎么做」这个更聪明的问法也试过了（下面那张卡），同样不行。

cora seal：clean 路由 − k1 +0.062；del 伤害 k1 +0.137 / k2 +0.208 / routed +0.204；CN 补边只恢复了 3.7% 的低证据对

问响应也会满仓：拼接门控同样不是修复

反事实拼接把「多一条证据，分数会不会上升」做成可测信号。结果两侧都失效：97–100 % 的 pair 分数都会上升，把拼接节点的特征清零后仍是如此（corr ≈ 0.95），所以它测的是「路径存在」而不是「证据饥饿」；而上升幅度对「哪些 pair 真的掉分」只有随机水平的区分度。收紧分位数只是沿 k1 ↔ k2 的轴回退，最好的设定仍不如不路由。
