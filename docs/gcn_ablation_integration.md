# GCN 消融代码与 SGDiff 仓库整合审查

审查日期：2026-11-12。对照本仓库 main `1eea63d39ea77c5402e96390042ee803513d73e6` 与 [GCN 实验 `9aabfe3`](https://github.com/linjunxiong/GCN/tree/9aabfe3e41c1d80d6756fc332d8c5a77412ac670)。

**结论：底层模型有明显重合，新增价值主要在输入消融、GCN 跨图迁移与实验留存。适合复用模型层，并把原实验协议作为单独入口整合，不宜直接合并两套结果。**

## related_work.md 与本次工作的关系

[related_work.md](related_work.md) 是 SGDiff 后续工作综述，围绕 C1 跨数据集迁移、C2 少标签、C3 结构攻击鲁棒性、C4 自同构/内存展开。它指出仓库已实现 PENCIL 等基线以及相关扩展方向；是否已实现需进一步核对代码，不能仅凭综述的方向表推断。

本次检查了 `scripts/run_experiments.py`、`sgdiff/engine/benchmark.py`、`baseline_trainer.py`、`factory.py`、数据和模型模块。现有迁移驱动针对 SGDiff；已有 GCN 基线没有我们完整的三组输入消融和 6×6 / 3×3 GCN 迁移组合。我们的工作可补充 **C1 的非扩散对照**；未因此验证 C2/C3/C4，也不构成对综述中外部论文或引用统计的独立核实。

## 影响可比性的实际差异

以下路径指审查时的 main；本分支只对 GCN 类新增方法，不修改下述现有协议。

1. **验证时传播图不同。** `sgdiff/engine/baseline_trainer.py::train_node_pair_baseline` 中 `eval_graph=graph.drop_edges(test_pos)` 同时供验证和测试使用，验证正边仍在验证传播图里。对于全图 GCN，这造成验证目标边可见；我们全过程仅用训练正边构图。测试时加回验证边本身可是一种协议选择，但与我们的训练图固定协议不同。子图方法另有目标边移除流程，不能将这一发现直接推广到所有模型。
2. **负边划分不同。** `sgdiff/data/splits.py::make_link_split` 分别采样每个集合，各次 `seen` 独立；负边可能跨 split 重复。我们的六组正/负样本两两不交。正边的取整和排列顺序也不同，即使同 seed 也不是相同划分。
3. **Hits 不是同一个指标。** `sgdiff/utils/metrics.py::hit_at_k` 返回合并正/负候选中 top-k 的正例比例，即 precision@k。我们计算正例击败全局负例池第100高分的比例，严格处理同分。两者都标为 Hit@100 时容易误比较。
4. **AP 同分处理不同。** 现有 AP 稳定排序后逐条累积；我们的 sklearn AP 按同分阈值处理。无同分时一致，存在同分时可能不同。
5. **输入与原始数据不同。** 本仓库属性按列标准化，无属性图使用17维对数度数编码；我们图内使用行归一化属性或 X=I，跨图使用32维度数编码与64维随机投影。数据加载器同名数据的来源不完全相同（USAir/NS 等）；需比对边集合和属性，不能仅凭名称认定一致。

最小实测（不用于评价模型质量）：100 条正例、100 条负例全部得0分，正例排在前面，现有指标返回 `AUC=.5, AP=1, Hit@100=1`，原实验返回 `AUC=.5, AP=.5, Hits@100=0`。另取30节点、满足 `(u+v)%5==0` 的无向边、seed=0，现有采样器 train/val 负边重合1条、train/test 重合3条。

要与 SGDiff、公平基准中的其他模型正式排名，应让所有模型使用同一原始图、精确 split、传播/目标边隐藏规则、特征预处理及指标定义后重跑。这里的模型整合不等于完成了这种全模型重评估。

## 实现方式

- 新增 `GCNEncoder.forward_preaggregated`：复用已有线性层，接受缓存的稀疏/稠密 `A_norm X`；X=I 时直接使用稀疏 A，避免 Pubmed 上的 N×N 稠密矩阵。后续层传播时先投影再聚合，偏置在聚合后相加；线性运算可交换，数学上与原路径一致。传 None 邻接即得到同深度 MLP。现有 `forward` 保留原行为。
- `experiments/gcn_ablation/shared_backend.py` 使用现有 `NodePairLinkPredictor` 和内积打分，映射原实验初始化并保持后续 CPU 随机状态。训练驱动、特征、指标继续复用存档代码，避免再写第三套流程。
- 原始代码和结果位于 `experiments/gcn_ablation/`；共享模型入口为 `run_shared.py` / `replay_shared.py`，使用独立结果目录并记录后端文件哈希。存档结果绝不标注为共享后端重跑结果。
- 原 benchmark、攻击评估、SGDiff 训练流程的行为保留。协议问题明确记录，后续可单独修复并重跑相关结果，避免本次整合暗中改变既有实验。

运行命令、超参数、数据来源和限制见 [实验说明](../experiments/gcn_ablation/README.md)。

## 验证

- 仓库测试：66 项通过（原59项 + 新7项），包括共享模型输出/梯度、初始化与 dropout 随机状态、稀疏单位矩阵输入、原 GCN forward 等价性和后端来源检查。
- 原实验测试：7 项通过，包含真实 Cora 的验证/测试边隐藏、训练图度数编码和迁移消融掩码。
- 共享后端实际运行：Cora、USAir，seed=0，最多20轮；覆盖 within/transfer 所有适用组，共8模型、10条目标评估。此为流程检查，不作为完整实验结果。
- 这8个模型的10组目标预测全部通过 checkpoint 回放；另用原实现运行相同短实验，对比20个正/负预测数组，最大绝对误差为0（当前 CPU 环境）。这不替代完整10种子重跑。

本分支没有重新训练全部10个种子的共享后端实验。历史结果依然对应原 GCN 仓库的实现与环境。
